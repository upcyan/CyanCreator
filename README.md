# CyanCreator 0.4.1

面向短片制作的本地 AIGC 工作台：创作简报 → 共享故事设定 → 大纲 → 剧本与分镜 → 单镜头视频 → 基础剪辑 → MP4。

采用 Node.js 本地服务与浏览器界面，支持本地模型下载部署及云端接入。源码仓库不捆绑权重；设置中心按需下载。当前提供短片基础剪辑，后续可以封装桌面壳。

## 启动

需要 Node.js 22 或更新版本。

```powershell
npm.cmd install
npm.cmd start
```

打开 http://127.0.0.1:3210 。项目存于 `data/workspace.json`，素材存于 `data/media/`。备份时停止工作台后复制整个 `data/`。单个数据目录只运行一个服务实例。

已安装 FFmpeg / FFprobe 二进制依赖；可用 `FFMPEG_PATH`、`FFPROBE_PATH` 指定自有版本。服务仅监听本机，不直接开放到局域网。`PORT` 修改端口，`CYANCREATOR_DATA` 修改项目目录。

## 更新现有安装

1. 保存页面中的编辑，等待生成、下载和导出任务结束。停止运行 `npm.cmd start` 的终端服务（Ctrl+C）；后台启动的实例也须先停止。停止后备份整个 `data/`，使用 `CYANCREATOR_DATA` 时备份实际数据目录。
2. 在当前安装目录检查更新：

   ```powershell
   cd E:\project\CyanCreator
   git status --short
   git fetch origin
   git log --oneline HEAD..origin/main
   ```

   `git status` 有本地改动时先自行提交或备份，避免覆盖；不要使用 `reset --hard` 强行更新。日志为空表示没有待拉取的远端提交。
3. 在干净的 `main` 分支应用更新。以下命令逐条执行，任何一步报错都先处理，不要继续启动：

   ```powershell
   git switch main
   git pull --ff-only origin main
   npm.cmd ci
   npm.cmd run check
   npm.cmd start
   ```

   `--ff-only` 遇到分叉会停止，不会强行覆盖本地提交。`npm ci` 按锁文件重装 Node 依赖，不删除项目数据或模型权重。上述路径是示例，实际操作使用自己的安装目录。
4. 服务启动后刷新浏览器。首次从旧版升级可按 Ctrl+F5 强制刷新；未保存的页面内容应提前保存。若原生依赖有更新，在设置中心再次点击独立运行环境的安装按钮，程序按依赖指纹同步环境，然后执行环境检查。

### 拉取代码后为什么可能没有生效

- **旧服务进程**：Node 在启动时加载服务模块和项目状态，`git pull` 不会自动重启。必须停止旧进程后启动新版；端口占用通常说明旧实例还在运行。不要在服务运行期间替换代码，以免前后端版本混用。
- **浏览器资源**：HTML、JavaScript、CSS 和 API 现已发送 `Cache-Control: no-store`。已打开页面仍须刷新；旧版留下的缓存首次升级使用强制刷新处理。
- **Python 依赖**：原生运行环境将依赖清单、PyTorch 版本与设备类型计算为安装指纹。重新安装时，指纹变化会同步依赖，安装失败不会写入成功指纹。拉取代码本身不会执行 pip，也不会自动升级已有环境。
- **模型与设置**：校验通过的权重复用属于正常行为，不是旧代码缓存。更新保留已有模型选择、参数和项目数据；新版默认方案不会覆盖用户配置，需要时手动载入新方案并保存。不要删除 `data/` 来清缓存。

也可使用 **设置中心 → 平台更新 → 检查更新 → 应用更新并重启**。仅支持官方 HTTPS origin 的干净 main 分支；有生成、下载或导出任务时拒绝应用。检查显示当前/目标提交及更新记录，应用固定目标提交，自动备份 `workspace.json` 到数据目录、快进更新、执行 `npm ci` 和检查、重启服务并刷新页面。完整素材备份仍按上文手动完成。

更新期间服务会暂时断开。失败详情保存在 `data/update-status.json`，重启日志在 `data/update-server.log`；若服务能够恢复，重新检查并应用可修复上次失败的依赖安装。若服务无法启动，按上文手动流程修复。更新不会自动回退代码；需要回退时停止服务，切回已知正常提交，执行 `npm ci`，并恢复与该版本配套的数据备份。当前 Node 安装须包含 npm，GitHub 私有仓库须已配置 Git 凭据；平台不会代填或保存凭据。

## 工作流与推理排障

工作流导航位于各创作页面标题上方；大纲页保留 A SPACE FOR YOUR NEXT STORY 条幅。模型连接、密钥与默认参数统一在设置中心维护，每个模型分类保留一个保存入口。镜头页只调整本次镜头参数，不再要求重复填写模型连接。剧本页负责生成和试听配音，后期剪辑页统一管理音轨位置、音量和淡入淡出。

剧本转换视频的顺序：保存场景与分镜 → 关联角色并填写景别/运镜等 → 视频生成页选择镜头 → “预览实际提示词” → 保存并生成。提示词在本地组合当前镜头、场景、角色外观、视觉设定与世界规则，**不额外请求文本模型**，不附带整部剧本、其它章节或对白。对白使用配音流程管理。预览显示字符数，不冒充精确 token 数；视频服务自身的计费方式不变。

伴写请求按阶段裁掉无关剧本和空字段，状态轮询仅返回章节目录，任务快照不重复保存所有章节历史。文本服务支持 SSE 时显示已接收字符进度；单次请求上限 10 分钟，开始流式返回后连续 90 秒没有数据会终止等待。服务只返回普通 JSON 时兼容接收，但无法显示逐段进度。

本地服务曾因 Windows 占用 workspace.json 导致原子替换报 EPERM 并退出，从而使取消按钮显示 Failed to fetch。现采用串行原子保存、非阻塞重试，并在持续保存失败时显示错误且保留内存状态；不能写入时不要关闭工作台，应排除磁盘/权限/文件占用后重试保存。此保护不替代定期备份。

取消原生生成会停止独立进程；文本接口取消会断开请求，上游是否立即释放推理资源取决于服务实现；云端付费任务可能继续执行。界面会区分连接失败与已确认取消，断连不等于取消成功。测试覆盖流式任务卡住后通过 HTTP 取消，并确认工作台继续响应。

原生 Wan 可先使用“低成本预览参数”（480×272、8 步、4 秒），确认构图再提高质量。逐层 CPU 卸载节省显存但可能明显变慢，CPU 模式只适合诊断。尚未对用户当前慢模型完成 GPU 吞吐基准，不承诺固定加速比例。

## 0.4 创作流程

- **多集多章**：大纲和剧本页顶部管理剧集、章节与标题。各章保留独立稿件、版本历史、审校状态和镜头版本；角色、世界书、媒体库及成片时间线为项目共享。旧项目自动归入第一集第一章。
- **手写与导入**：直接编辑节拍、场景、对白和镜头，支持增删、排序；导入 TXT、Markdown 或结构化 JSON 后先检查预览，再保存。文本按标题拆段，不会擅自替你改写对白。JSON 可从页面导出。
- **AI 伴写**：保存当前稿后选择续写、润色、扩写、重新构思或拆解分镜，填写要求。完整候选稿与当前稿对照预览，点击应用后才替换，并保存历史；须回到任务所属章节才能应用。
- **角色与世界书**：可手写人物外观、性格、动机、关系和声音设定，也可 AI 生成人物候选。世界书支持视觉、规则、地点与历史条目。共享设定变化后，已有章节标记待确认。
- **分镜流水线**：按镜头展示稿件、视频任务、候选素材、选定版本与剪辑状态。景别、运镜、灯光、景深、画面编排、走位和关联角色会进入实际视频提示词；模型不一定精确执行所有摄影指令。

### 角色立绘与参考图

在设置中心配置“角色立绘与参考图模型”，再在剧本与分镜页选择已保存角色，生成全身立绘或三视图。支持兼容 Images API 的云端/本地服务，以及无需 ComfyUI 的本地 AUTOMATIC1111 API（需自行启动带 `--api` 的服务，地址通常为 `http://127.0.0.1:7860`）。模型 ID、画布和密钥引用可配置；不会自动安装 Stable Diffusion。

生成图片保留为候选，可预览后选为角色参考；也支持导入 PNG/JPEG（最多 20MB）。参考图会显示在关联分镜中，切换参考版本不删除历史图片。当前视频适配器使用文字提示词，**不会自动将角色参考图片作为视频模型的图片输入**；三视图质量与跨图一致性取决于选用模型，当前不提供人脸训练或角色 LoRA。

### 云端视频模板

设置中心可载入 Seedance（火山方舟）、可灵及 Veo（Gemini API）文生视频模板，也保留 MiniMax。填写账户可用的模型 ID、服务地址和密钥引用后保存。可灵需要 Access Key 与 Secret Key 两个引用；Veo 使用 Gemini API Key。

模板执行真实提交、状态轮询和素材下载。模型名称与权限以服务商账户为准；模板不是所有后续型号的通用能力声明。Seedance 基线为 4–12 秒，可灵为 5/10 秒，Veo 为 4/6/8 秒，高分辨率等组合仍受上游限制。不会自动重试付费提交。三个新云视频协议通过模拟服务验证，尚未使用真实付费账户生成视频。

### 配音与配乐

设置中心的 AI 配音支持 **本地 Piper 中文**、兼容 Speech API 的云端服务与 ElevenLabs。Piper 使用独立 Python 环境和 CPU，无需 ComfyUI；填写部署设置中的 Python 路径后点击“下载并部署本地语音”，任务记录显示安装和下载进度。固定 Piper 1.8.0 与中文 huayan medium 权重，下载使用 SHA-256 校验。Piper 引擎采用 GPL-3.0，音色另以模型仓库许可为准。

在剧本页填写配音文本或载入本章对白，指定角色、云端音色 ID 与语速，生成后试听。支持导入配音/背景音乐，设置成片位置、素材入出点、音量、淡入淡出，实际 FFmpeg 导出会混合原声和多个音轨。当前音轨时间以整个项目的成片时间线为准，不是每章单独起算。提供音乐素材管理与混音，未提供 AI 作曲、声音克隆或自动对口型。

本机已完成 Piper 权重下载与真实中文合成，测试音频约 5.76 秒；这不代表所有云端音色或其他设备均已验证。

### 云端密钥保护

设置中心 → 密钥保险库：填写引用名（例如 `ARK_API_KEY`）和 Key，点击加密保存，再在相应模型配置中填写同一引用名。保存后不回显，不写入浏览器 localStorage、项目 JSON 或导出的模型配置；服务端只在调用时读取。移除保险库值后，同名环境变量仍可能生效。

Windows 使用当前账户 DPAPI，密文位于 `data/secrets/vault.dpapi`，该目录由 Git 忽略。保险库值及调用过的环境变量密钥会从任务错误消息中脱敏；请求不把密钥带给第三方素材下载地址。整个工作台仅供本机可信用户使用：同一系统账户下的恶意进程或管理员仍可能访问内存或解密能力，不能承诺绝对防泄露。

跨机器/跨账户复制保险库可能无法解密，此时服务拒绝加载该保险库。请保留原备份，在停止工作台后移走不可解密的 `vault.dpapi`，重启并重新配置密钥；不要把明文 Key 放进模型地址、项目设定或 Git。非 Windows 平台使用环境变量，内置保险库暂不支持。

新增回归覆盖多集章节切换、伴写候选保护、角色图两种协议与真实图片入库、图片/视频素材隔离、跨项目引用拒绝、密钥密文保存/重载与 API 不回显、真实 FFmpeg 音轨混音。图片服务使用明确的协议 fixture，尚未实测真实云端绘图或本地 SD GPU 推理。浏览器已实测角色/世界书保存、新建与切换章节、参考图导入及选定、关联分镜的图片显示、配音加入音轨与音量保存；设置中心齿轮、品牌图标和深色界面布局已检查，控制台无错误。图库导入验收使用明确的测试图片，不作为 AI 绘图质量证明。

## 大纲与剧本的模型设计

设置中心使用**共享模型配置 + 阶段引用**：服务地址、模型名称、密钥环境变量和默认生成参数只填写一次。故事大纲、剧本与分镜、一致性审校通过下拉框选择该配置。

可以新增或复制多套本地/云端配置，并用“三个阶段共用”快速分配。默认大纲和剧本继承共享参数；审校默认单独使用较低温度。打开“独立调整生成参数”可覆盖温度和输出长度，服务与模型仍共享。被引用的配置不能删除，先调整阶段引用即可。

旧版三份配置会自动合并相同的服务/模型/密钥引用，保留各阶段原有参数差异；已有任务继续使用提交时的参数快照。`CYANCREATOR_DATA` 指定数据目录，同时兼容旧环境变量 `LOCALCREATOR_DATA`。目录改名后，托管素材路径会在启动时重新定位。

写作采用**一个本地指令模型、三个独立角色**，不为每个阶段训练模型。

1. **故事架构师**：输入创作简报与故事设定，输出 logline 和因果节拍。温度初值 0.7；先衡量结构完整性、动机与结尾回收。
2. **编剧 / 分镜导演**：读取同一设定及已确认大纲，输出场景、动作、对白和 4–15 秒镜头提示词。人物外观、场景、运镜与声音应写入每个独立镜头。
3. **审校**：温度初值 0.2，检查动机、角色口吻、时间线及镜头可执行性，返回问题与修改建议，不直接覆写稿件。

本地模型库提供 Qwen3 8B Q4_K_M 作为写作候选，以及 Qwen2.5 0.5B Q4_K_M 用于轻量连通测试。模型名称使用运行环境实际暴露的 ID；不同量化文件、上下文长度和 KV cache 都会影响显存，不能只按参数量估算。小模型连通成功不代表长篇写作质量达标。

按当前章节发送创作上下文，并附带项目共享角色与世界书；章节摘要检索与按场景增量重写尚未实现，长篇应拆章控制上下文长度。

需要更强推理时，可以只把大纲或审校路由到云端。用户主动选择云服务后，相关创作简报、故事设定和已有稿件会发送给该服务。密钥可在设置中心的保险库填写，例如使用引用名 `TEXT_API_KEY`；项目与模型配置只保存引用名，密钥值由本机 DPAPI 加密保存。也兼容同名环境变量。

## 本地部署

### 不依赖 ComfyUI 的原生视频工作流

设置中心选择“原生 Wan”，在部署设置填写 Python 3.12 路径，然后安装“独立运行环境”。程序在 `data/runtimes/` 创建独立环境，安装固定版本 PyTorch 与 Diffusers。NVIDIA 使用 CUDA；CPU 仅供诊断，当前没有适配 AMD 加速。

下载“Wan 2.1 · 原生独立部署”后载入方案并保存。官方 Diffusers 权重共 19 个文件，约 28.9 GB，存于 `data/models/wan21-native`，不复用 ComfyUI 权重。下载校验和续传与其它模型共用。支持 BF16/FP16、模型或逐层 CPU 卸载、VAE 分块；这些选项不执行权重量化转换。

视频生成页提供分镜列表、单镜头提示词与参数、批量提交、原生采样进度、取消、生成版本选择和加入时间线。任务保存参数快照，模型切换后不会错误沿用其它模型的镜头参数。原生推理使用独立子进程，结束或取消后释放该进程；ComfyUI 和云端仍可选择。

### 一键下载与部署

设置中心 → 本地模型库 → **下载并部署**。下载清单固定官方仓库版本、文件大小与 SHA-256，支持 HTTPS 官方分发重定向、磁盘空间检查、`.part` 续传、取消和重试。校验不符的已有正式文件不会被覆盖；损坏临时文件会移除后提示重试。

- **文本**：下载 GGUF 到 `data/models/text/`，自动安装已固定版本的 Windows x64 llama.cpp Vulkan 到 `data/runtimes/`，启动本机服务并检查 `/v1/models`。完成后新增共享配置，可用“三个阶段共用”分配；不会覆盖已有写作路由。
- **视频**：Wan 2.1 1.3B 约 9.83 GB，H3 约 42.47 GB。下载到部署设置中的 ComfyUI 模型目录，检查所需节点与权重。点击“载入视频方案”并保存即可切换。新工作空间默认使用 Wan，现有配置保留。
- **运行环境前提**：文本自动安装当前支持 Windows x64；Vulkan 依赖显卡驱动，GPU 层数设为 0 可用 CPU。原生视频只需独立 Python 3.12。选择 ComfyUI 视频方案时需要预装 ComfyUI；自动发现本机 Desktop，也可填写路径。可启动已有 ComfyUI，尚不自动安装其环境。
- **状态**：下载与部署串行执行，记录进度和错误；重启后标记中断，重试会校验并续传。部署完成代表服务/权重检查通过，不代表视频推理已完成。工作台启动的服务可以停止并释放显存；外部启动的服务由原服务管理界面管理。
- **诊断**：日志在 `data/runtime-logs/`。重复“检查并启动”会验证已有文件并复用正确的已运行模型服务。关闭工作台会停止本次由其启动的模型服务。

目录扩展入口为 `lib/model-catalog.js`（固定下载清单）、`lib/video-presets.js`（模型工作流与帧数策略）和 `lib/local-runtime.js`（推理进程）。ComfyUI 适配器按工作流执行，不依赖 MiniMax 模型名称；新增其他协议的云服务需要对应适配器。

### 可选 ComfyUI 后端

在设置中心点击“载入视频方案”（MiniMax H3）→ 保存 → 检查本地部署。内置方案基于官方 ComfyUI 原生图，包含视频与音频解码，使用：

- `minimax_h3_fl2va_pruned_int8_convrot.safetensors`
- `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors`
- `minimax_h3_video_vae_fp16.safetensors`
- `minimax_h3_audio_vae_fp32.safetensors`

可通过模型库下载，或按照官方部署文档手动放入对应目录。开发验证未下载上述大体积视频权重，没有将其实际生成能力作为已验证结果。

基线为 864×480、约 5 秒、20 steps、固定 seed，先验证完整链路再升画质。INT8 / NVFP4 由上述实际权重承担；界面不执行权重量化转换。注意文本编码器本身也很大，显存不足时需在实际推理环境启用支持的卸载策略，并检查系统内存峰值。

工作台串行提交自己的任务，但不会自动卸载其它软件占用的模型，也不会中断 ComfyUI 中其它用户的任务。运行视频前，在文本推理环境中卸载文字模型。参数优化以真实耗时、显存、画面连续性、角色一致性和音画同步为准；当前只自动记录耗时和配置。

### 硬件兼容性

原生视频后端当前支持 NVIDIA CUDA 和 CPU 诊断模式。ComfyUI 的硬件兼容性取决于其安装环境、节点与权重；AMD 加速尚未验证。按实际设备选择后端和显存卸载策略，工作台不预设设备数量或机器分工。

## 参数与工作流

ComfyUI 须导出 **API 格式**，不是含 `nodes` 的界面 JSON。参数绑定支持一个输入或多个输入，例如：

```json
{
  "prompt": {"node": "5", "input": "prompt"},
  "steps": {"node": "9", "input": "steps"},
  "frames": {"node": "5", "input": "length"}
}
```

所有 `params` 字段都必须存在对应绑定；不能用一个无实际节点对应的“int4”开关冒充量化。调 CFG、LoRA、量化模式或卸载参数时，先确认导入工作流包含相应节点。内置 H3 基线使用 BasicGuider，不提供不生效的 CFG 滑杆。自定义图可关闭 H3 时长换算，使用图自身的固定帧数。

云端 V1 仅接受其 API 支持的参数，不传递本地 steps / 量化设置。云 API key 通过保险库引用或环境变量 `MINIMAX_API_KEY` 读取，服务地址使用 `https://api.minimax.io/v1`。设置环境变量后重启工作台。
